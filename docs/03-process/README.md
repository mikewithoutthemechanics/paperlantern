# Process

How PaperLantern works: **Diagnose → Build → Compound**.

We don't hand you a deck. We ship the system — and show our work.

1. **Diagnose** — We map where visibility is actually breaking down before proposing anything.
2. **Build** — We design and ship the system itself — not a recommendations document.
3. **Compound** — We stay in the system as it runs, refining instead of resetting every quarter.

---

## Phase 01 — Diagnose

**Goal:** Understand where visibility is breaking.

### Steps

1. Discovery call and business context
2. Stakeholder interviews
3. Audit of existing positioning, content, and distribution
4. Identify visibility bottlenecks (not symptoms)
5. Deliver a **visibility breakdown map**

### Deliverable

A map, not a deck. The client sees exactly where the system is leaking and what fixing it will move.

---

## Phase 02 — Build

**Goal:** Ship the exposure system.

### Steps

1. Lock differentiated positioning
2. Build the content engine (found + redistributed, not just posted)
3. Wire distribution into existing operations
4. Build the supporting infrastructure (site, booking, CRM, publishing, tracking)
5. Launch and iterate

### Deliverable

Working infrastructure. Not a recommendations document.

---

## Phase 03 — Compound

**Goal:** Keep the system running and make visibility compound.

### Steps

1. Operate the system month-to-month
2. Refine based on real data
3. Scale output through AI amplification
4. Report on outcomes, not vanity metrics

### Deliverable

Compounding growth with monthly refinement, instead of a quarterly reset.

---

## Principles

- **Ship, don't speculate.** Recommendations documents are not deliverables.
- **Show the work.** Evidence beats promises.
- **Compound, don't reset.** The system keeps working after the build.
- **Outcomes over deliverables.** We care about results, not line items.
